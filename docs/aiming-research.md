# Aiming cue source findings

Research and implementation notes for adapting HarbourMasters/Shipwright PR 5435 to the current spatial cue engine. The aiming cue and remappable target switch are installed in build `39252ed56941`; in-game behavior remains untested. Amethyst's decision is recorded in `H:/projects/ocarina/aiming-questions.md`.

## PR behavior

`ActorAccessibility_RunAccessibilityForActor` gates aim help on `PLAYER_STATE1_FIRST_PERSON`. Ordinary weapon targets also require `PLAYER_STATE1_USING_BOOMERANG` or `PLAYER_STATE1_ITEM_IN_HAND`; `AIM_CUP` targets can sound in plain first-person view. When `player->unk_6AD == 2`, held bow variants, slingshot, hookshot, longshot, boomerang, and no item select different target masks. Hookshot and boomerang range is 380 world units, longshot is 770, and the default range is 1000. The PR checks each target's player distance independently and can play multiple target sounds together. Leaving first-person view resets each target's next-pulse counter.

`ActorAccessibility_ProvideAimAssistForActor` uses the player's `actor.focus.rot.x` and `actor.focus.pos.y` to estimate the aim ray's height at the target's horizontal distance. The difference from target height controls pulse frequency: `1 + uint8_t(verticalDifference / 5)` game frames within 300 units, and 30 frames above that. Pitch marks below, aligned, or above. Yaw difference from `player->yaw` controls volume and pan, but does not affect pulse frequency. The `tolerance` assigned to a few targets is unused in this code. The PR's 1-frame minimum can retrigger the sound before the current pathfinder recording completes; the recording in this project is 4001 samples at 32 kHz (about 0.125 seconds), so the interval needs a floor if it is reused.

## Target rules in PR 5435

The PR sets masks for: eye and crystal switches (`ObjSwitch`); the Lake Hylia sun (`ShotSun`); hookshot pillar, Water Temple platform, scarecrow, unopened chest, small crate, and flagpole; invisible `EnWonderItem` hit targets; Jabu-Jabu yellow switches; Phantom Ganon; active Forest Temple paintings and Poe sisters; Lake Hylia hookshot object; statue eye; Keese; gold token and wall skulltulas; Freezard; and silver-rupee puzzle targets. It also has fixed Lost Woods room 1 and Ice Cavern room 9 targets. Exact PR masks and predicates are in `AccessibleActorList.cpp`; some are state dependent rather than actor-ID-only.

The current native source confirms several important state fields: `EnWonderItem.wonderMode` and its hit-type encoding in `z_en_wonder_item.c`; Water Temple platform type in `z_bg_mizu_movebg.c`; scarecrow switch state in `z_en_kakasi2.c`; and Forest Temple painting visibility through `BgPoEvent_PaintingPresent` in `z_bg_po_event.c`. The PR calls `Ship_BgPoEvent_GetPuzzleState`, which the current source does not expose. The native painting action is a viable state source to verify when implementing that target. The `ShotSun` actor refreshes `hitboxPos` under its own range and time conditions in `z_shot_sun.c`; its world position alone is not the sun's aim point.

Two PR predicates must not be copied as cached flags. `accessible_switch` assigns an eye switch's aim mask when the subtype is nonzero or `eyeTexIndex == 0`, but does not clear an earlier mask when that condition becomes false. The new reader should calculate this from the live `ObjSwitch` field each update; the current `z_obj_switch.h` distinguishes floor, rusty floor, eye, crystal, and targetable crystal. For the Lake Hylia sun, `ShotSun_UpdateHyliaSun` refreshes the collider and `hitboxPos` only while the actor's horizontal distance to Link is at most 120 and the time is in the `0x4555` to `0x5000` window. Aiming must use that same eligibility gate before reading `hitboxPos`, or it could point to a stale value.

## Current integration

`CueActors.cpp` tracks actors through `OnActorInit` and `OnActorDestroy`, and stops all ordinary cues while Options, pause, or a cutscene is active. Its existing `Available` rejects actors without a draw function; `EnWonderItem` deliberately has no draw function, so aiming needs its own availability predicate. `CueMixer` decodes cue WAV files at startup and renders a fixed voice pool. `Cue::Pathfinder` is already loaded. `Navigation_PublishAudio` uses the pathfinder recording with `KeepPlayingInterval` in a reserved guidance voice. An aim cue needs its own voice identity and saved On/Off and volume controls even though it shares the recording. Source position and listener orientation are available through `SpatialAudio_WorldSource`.

The dynamic target predicates were checked against the current actor headers and consumers before implementation. The final tool-switching, target-loss, menu, pause and first-person behavior still requires Amethyst's in-game test.

## Installed implementation and native switching limit

`AimCue.cpp` registers `OnActorInit` and `OnActorDestroy` for the PR's twenty supported actor IDs. `UpdateAimCue` reads the player's first-person state and held item, then calculates each eligible actor's live mask and point. The two fixed Lost Woods and Ice Cavern targets are tagged in `CueLocations.h`. The Lake Hylia sun uses its live collider point only inside its native range and time window. Forest Temple paintings require `BgPoEvent_PaintingPresent`, rather than the PR-only puzzle-state accessor. Invisible `EnWonderItem` targets remain eligible through their update state. A destroyed actor is removed immediately.

The listener gets one pathfinder recording from the candidate with the smallest combined yaw and pitch error. A five-hundredths-radian margin keeps the existing target from flapping when two candidates are almost tied. The interval ranges from 0.16 seconds at alignment to 1.5 seconds at larger errors, long enough for the 0.125-second recording. The aim sound has its own `A11yAudio.aim.Enabled` and `.Volume` settings, both defaulting to On and 50; Reset all clears them. Cue preview reuses the pathfinder recording but reads the aim volume. `CueMixer::KeepPlayingPulse` uses an ordinary voice and keeps the navigation guide's reserved voice separate. The spatial audio checks verify pulse timing across different render block sizes and voice capacity.

The current `z_player.c` contradicts the initial idea that native Z-target switching could select an aim-cue target. `Player_UpdateZTargeting` cycles native lock-ons on Z press, but the first-person weapon action exits when `focusActor` becomes non-null, and the first-person update also clears `PLAYER_STATE1_FIRST_PERSON` when `Player_IsZTargeting` becomes true. The aiming cue therefore auto-selects the target nearest the aim line until the player deliberately switches.

Amethyst approved Xbox X as the default switch and asked for ordinary keyboard and gamepad remapping. `OTRGlobals` registers `BTN_AIM_CYCLE` at `0x01000000`, above all existing N64, virtual-stick and custom ocarina bits. The port compiles controller masks as `uint32_t`. The control deck gives it Xbox X and keyboard V defaults, with a one-time migration for existing configurations. Controls, Configure Controller, Link (P1), Buttons exposes the binding. The existing mapping editor handles capture, saving and restoration of defaults. `PadMgr_Update` casts the first press-button path to `u16`, so `AimCue` reads `play->state.input[0].cur.button` and waits for release before another cycle.

`AimCue` orders eligible targets by live left-to-right bearing, distance and identity. A press advances once and holds the selected target while it stays eligible. The spoken response uses a localized list position, relative direction and Navigation's approximate walking-step text; it adds above/below when the target is vertically separated. When a target is lost, automatic selection resumes. Leaving first-person or opening Options stops the sound and clears the manual selection. These input, selection and speech paths still need Amethyst's in-game check.
